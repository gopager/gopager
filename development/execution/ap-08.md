### E-09 Post-correction Publication Defects and Repair

Date: 2026-11-05. Review against C-05 found two T061 defects in the existing implementation:

1. **No publication after completion.** `MarkPending` sets the affected Transmissions/Messages to `pending` and contributions unready, but `CompleteCorrection` did not restore readiness. Processing reconciliation runs only for already-selected candidates, so a corrected scope stayed unpublished indefinitely.
2. **Rebuilt contributions under a ready Message.** `rebuildMessageContributions` marks every rebuilt contribution unready. A Message whose Transmissions were already `ready` (for example, intake into a new Message during correction, then dirty capture) kept `ready` status with permanently unready contributions.

Before coding, the binding behavior was recorded at [C-05 post-correction publication re-entry](../contracts/c-05-matching-correction.md#post-correction-publication-re-entry) and linked from [C-08](../contracts/c-08-events-jobs.md#ap-08-master-data-and-correction-facts). The implementation is in AP-08 write scope (T061 Processing publication participation): `ApplyCorrectionBatch` returns each rebuilt Message and its Transmissions to `pending`; the required `assignments.CorrectionPublication` participant ([interface](../../internal/assignments/correction.go)) is implemented by the Processing source owner in [source_reentry.go](../../internal/persistence/ent/ingeststore/source_reentry.go) and composed in [main](../../cmd/gopager/main.go) through [the Processing runtime](../../cmd/gopager/processing_management.go); the runner performs a bounded re-entry pass whenever no correction is claimable. The Transmission Ent schema and unreleased migration `00011` gained the partial index `transmissions_unpublished`; `go generate ./internal/persistence/ent` exited 0.
