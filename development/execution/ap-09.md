### E-08 Fail-closed list filters (security review)

Date: 2026-11-07. An automated security review flagged the Gateway list filter: a reach that is not `all` and has no Agencies (for example a restricting key that does not overlap the owner's grants) passed a nil slice, PostgreSQL received NULL, `agency_id = ANY(NULL)` is NULL inside `NOT EXISTS`, and every Gateway with Networks became visible. The Network list was fail-closed in that case. Fix: both `ListGateways` and `ListNetworks` return an empty page for an empty reach, pass a non-nil slice, and use `coalesce($2::uuid[], '{}')` (Gateways: `agency_id <> ALL(...)`). Test `TestListsFailClosedForAnEmptyReach` (nil, empty and non-overlapping reach list nothing; a covering reach lists the Gateway). Commands: `GOPAGER_INTEGRATION=1 go test -race -count=1 ./internal/persistence/ent/ingeststore/` ok; `GOPAGER_INTEGRATION=1 go test -count=1 -run 'Management|Delegation' ./cmd/gopager` ok; `make` exit 0; `go test ./...` ok. Limitation: the new test was not separately run against the unfixed code.
