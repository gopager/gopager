## Planning Before Coding

Record query/live decisions in C-07, fields/actions in C-06 and consumption in C-08 before coding.

T063 binds query/detail/filter/order/page-token schema/version/errors. Ordering and time filters use the stored Message time (the earliest observation of any member); the page token is a stateless HMAC keyset token on `(first_observed_at, message_id)` whose key is a random 32-byte secret generated at first start and stored in PostgreSQL (new migration in scope), shared by all instances, with no operator setting; the token has no expiry and is invalid when filters or Principal differ; there is no `total` and there are no option counts; per-Unit first times appear in details and age limits use the per-(Message, Unit) anchor (D-135 replaced the per-query View time and server-side continuation state). Filters by Agency replace Network filters; Radio network and Protocol stay technical dimensions. Field filters are validated against the author's readable field groups at save time. T063 also binds authorization-before-pagination and locale-independent wire values. Settle remaining field-group/filter/operator/option eligibility using [C-06](../contracts/c-06-identity-authorization.md) and [REQ-135..137](../requirements-catalog.md#n-delegated-administration-and-restricted-views), preserving fixed global fields and C-07 Unicode/grouping/time/page bounds. Payload-only and selected-Unit queries cannot expose hidden technical/Unit/Organization fields through filters/options/counts/details. Bind the AP-08 assignment state into the projection: suppressed Transmission targets are excluded from views, search, details and live updates (REQ-123); a correction in progress is distinguishable from completed (REQ-035); an undecidable or failed assignment is distinct from "no matching Unit" (REQ-040); the encrypted-assignment label is shown without implying decryption (REQ-124); unassigned traffic is visible to the Agency owning the resolved Network and only with the explicit "without Unit" grant (REQ-056, D-135 item 5).

T063 owns server saved views for [REQ-133/138](../requirements-catalog.md) under [D-142](../decisions/09-process-and-documentation.md#d-142): personal and global ownership, CRUD with revisions, private definition access, a global view visible to every Principal that may read Messages, opening any view yielding only the intersection of its filter with the viewer's current Message and field rights, unavailable-field handling on reopen, and management HTTP. The policy is recorded in the C-07 planned section (C-06 references it); T063 binds finite cases for private access, delegation, hidden-field reopening and global visibility. `network_unresolved` is exposed as a boolean only to Principals holding the Network/Agency scope (REQ-046). Field groups are the existing ones of [HTTP API: Authorization](../../docs/http-api.md#authorization); no group is added. REQ-108 search admission: 60 per minute per Principal or key ([C-06](../contracts/c-06-identity-authorization.md)), configurable by `--search-attempts-per-minute`, guests keyed by client source like the login source buckets, stored in PostgreSQL like the login limiter, rejected with `RATE_LIMITED` and `Retry-After`. Projection ownership: this AP projects the derived Processing result fields (field group `derived`) in feed, detail, filter and order and consumes `processing.completed` as the upsert trigger; AP-13 builds only the GUI card model on top.

T064 builds the missing consumer framework on the implemented reader port (LISTEN wake-up listener, consumer runner with poll fallback, offset advance in the effect transaction, blocking on unknown fact versions, lifecycle registration in `cmd/gopager/`) and the live source on the sequenced `domain_events` log. The stream request carries the client's loaded Message-time range (`from`, optional `until`); the server filters pushed events by the `messageTime`/`previousMessageTime` they carry before the view filter (REQ-005, no live-age window), and the client reopens the stream with an extended range after loading a further page. Resume is by the opaque gap-safe `(txId, seq)` position: the page cutoff and the SSE `id`/`Last-Event-ID` carry it, the cutoff is taken in the same snapshot as the page query (replacing `asOfSeq`), an unavailable position yields `resync-required`, and the replay window is the 24 h `recordedAt` bound of [C-08](../contracts/c-08-events-jobs.md), set by a configurable flag documented in operations. T064 also settles canonical lookup, unknown-version/missing-ref outcomes, revisions/current rights, durable receipt/resume/work state before transport Ack, and retention/resync. It handles `assignment.changed.previousNetworkId` (possibly empty targets) in live remove/replace and binds AP-08 correction, AP-09 `gateway.state-changed` and `processing.completed` facts. It requires no AP-11 Delivery consumer and treats consumer offsets as no domain idempotency.

T063/T065 own REQ-108 query/search admission, bounded configurable policy, safe error/retry metadata and shared-IP fairness, with real multi-Principal/multi-tab tests; page/deadline limits do not substitute.
