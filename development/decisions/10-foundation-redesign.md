## D-135 Foundation redesign after the 2026-11-06 re-evaluation

- **Status:** accepted; item 9 amended by [D-137](#d-137)
- **Date:** 2026-11-06
- **Supersedes:** [D-25](04-processing-and-plugins.md#d-25) (barrier semantics), [D-77](04-processing-and-plugins.md#d-77), [D-79](04-processing-and-plugins.md#d-79), [D-82](04-processing-and-plugins.md#d-82), [D-92](05-events-and-delivery.md#d-92), [D-93](05-events-and-delivery.md#d-93), [D-94](05-events-and-delivery.md#d-94), [D-123](05-events-and-delivery.md#d-123), [D-124](05-events-and-delivery.md#d-124); in part [D-03](01-platform-and-storage.md#d-03), [D-14](01-platform-and-storage.md#d-14), [D-22](07-query-and-live.md#d-22), [D-24](04-processing-and-plugins.md#d-24), [D-28](07-query-and-live.md#d-28), [D-31](01-platform-and-storage.md#d-31), [D-32](01-platform-and-storage.md#d-32), [D-76](04-processing-and-plugins.md#d-76), [D-88](05-events-and-delivery.md#d-88), [D-90](05-events-and-delivery.md#d-90), TECH-05 (SQLite half) and TECH-07.
- **Decision:** A user-ordered first-principles re-evaluation of every planning document and the implemented code, including a cost/use review of all user stories, replaced the following foundations. The items are numbered as in the original record.
  1. **PostgreSQL only.** The SQLite adapter and the Lite/Full dialect split are retired. "Lite" is a single-host deployment profile: one `gopager` start with PostgreSQL as a compose sidecar (the Lite compose profile). An application-managed PostgreSQL child is considered only if a bare-metal single-binary Lite is required later. `--profile` is removed. REQ-116's crash-loss allowance is dropped and REQ-119's transfer mechanism is dump and restore of one engine.
  2. **No publication barrier.** Accepted evidence is visible on commit with `processing_status` `none | pending | completed | failed`; Workflow results attach when done and `processing.completed` triggers result-dependent reactions.
  3. **Agencies.** An Agency is the operating authority of one alerting domain (for example a county's fire dispatch centre; the police of the same county is another Agency). The working name "District" was rejected by the user as geographic; "Agency" was chosen after a naming review against the glossary. Every Radio network (code identifier `network`, exactly one Protocol) and every Unit belong to exactly one Agency. Grant scope kinds are `all | agency | unit | unitCollection | account`; the `network` scope kind is dropped. GoPager has no mutual-aid logic: a Unit belongs to one Agency, and a resource shared by two districts is a rare edge case without special support. A physical alarm channel shared by two districts with separate address prefixes is modelled as one Radio network per district, each owned by its Agency.
  4. **Address-based Network inference is kept** (a reversal of an earlier drop, decided by the user on 2026-11-06). Intake resolves the Network, within the Gateway's Networks of the submission Protocol, in this priority order: the declared Gateway Network identifier, the only Network, the only Network whose address rules match, the highest-priority Network among several that match, and, when none matches (also for targetless input), the highest-priority Network. The per-Gateway Network priority is a unique number set `0..n-1`, lower first.
  5. **Unmatched targets are visible as unassigned.** A target that no rule matches, and targetless input, stays visible as unassigned traffic to the Agency that owns the resolved Network; the unassigned view is therefore decided per Agency, not globally.
  6. **Contributions become a cache.** `message_units` is maintained at intake and refreshed per affected Message; `contribution_supports` and the duplicate `transmissions.targets` are removed.
  7. **Correction scoped by selector.** Rule, Unit-deletion and Suppression changes compute the affected target set through typed address columns and enqueue that selector; nothing is hidden and there is no dirty capture. A Processing run's context is the assignment revision of its own targets.
  8. **Locks.** Readers take shared locks and use optimistic `access_revision` checks; only writers that change rules, Workflows or access take `FOR UPDATE` on their control row first; Grouping serializes per Payload identity with an advisory lock; the schema check leaves the per-transaction path.
  9. **Processing runs.** `processing_runs` replace revisioned candidates (claims with `SKIP LOCKED`, `NOTIFY` wake-ups, Operator-configurable concurrency and poll); plugin processes are pooled per instance and started with `SecureConfig`; an invocation-envelope `mode` replaces the separate preview artifact.
  10. **Events.** One sequenced `domain_events` log (`seq`, `tx_id`) with gap-safe consumers and `NOTIFY` replaces the Watermill reference publication; one `assignment.changed` fact per Transmission.
  11. **Query.** Feeds order and filter by the stored Message time (earliest observation of any member); page tokens are stateless HMAC keyset tokens; SSE resumes by event sequence.
  12. **Authentication.** Expiry is checked uniformly in the central authentication handler: every service, login-adjacent path and the early body-protection check reject an expired session or key with `LOGIN_REQUIRED`. Guests are read-only: an anonymous request may view and filter, and any state-changing method is rejected before its body is read.
  13. **Field permissions** stay global (D-69). Information-flow classification is replaced by save-time validation of selectors, filters and templates against the author's readable field groups and one classification per Workflow definition version.
  14. **Code structure and toolchain.** HTTP adapters live in `internal/httpapi/`; stores lock only their own tables; Workflow actions are `workflow.*` instead of `rule.*`; the toolchain is Go 1.27.3.
  15. **Story simplifications.** REQ-062 cleanup is one transaction plus `principal.deleted`; REQ-072/076 recovery requests and automatic dispatch are dropped; REQ-090 webhooks start with POST JSON, Bearer and HMAC-SHA256; REQ-094 stays a requirement with one declarative layout definition rendered by the frontend and the Core; REQ-096 becomes a static banner; REQ-129 uses per-integration Unit parameters; REQ-005 keeps live updates for loaded Messages through a range-filtered stream; REQ-077/078 keep action and scope restrictions only; the D-51 Grouping window gains a one-day product cap; REQ-128 import/export is promoted into AP-15/AP-16; REQ-121 EAS stays until the user confirms that no deployment needs it.
- **Consequences:** C-04, C-05, C-06, C-07, C-08, C-11 and C-12 and the glossary are amended at their owners; migrations are edited in place under [D-128](01-platform-and-storage.md#d-128). Code changes are recorded as "Follow-up (D-135)" entries with E-IDs in the execution records of AP-05 to AP-08; `docs/`, OpenAPI and Go doc comments change with the code. Open AP-09..AP-16 texts are corrected inline. Process slimming (this ADR set and one approval gate per package) is part of the same decision.
- **Owner detail:** [Architecture](../architecture.md), [glossary](../glossary.md), [execution records](../execution/README.md), [docs/architecture.md](../../docs/architecture.md).

## D-137 Processing work record as implemented

- **Status:** accepted
- **Date:** 2026-11-07
- **Amends:** [D-135](#d-135) item 9
- **Decision:** The Processing work record stays `processing_candidates`; the table replacement by `processing_runs` named in D-135 item 9 is dropped. The implemented parts of item 9 stand: due candidates are claimed with `FOR UPDATE SKIP LOCKED`, intake wakes the worker through `NOTIFY`, and concurrency and poll interval are Operator-configurable ([AP-06 E-19](../execution/ap-06.md#e-19-dispatcher-skip-locked-selection-notify-wake-up-renewal-tolerance-flags)). Plugin pooling with `SecureConfig` and the invocation `mode` are unaffected. The rename would cost a migration and a broad refactor without a behavior change.
- **Consequences:** Candidate supersession on a changed Workflow, version, source or assignment context remains as implemented and documented in [docs/architecture.md](../../docs/architecture.md); D-77, D-79 and D-82 stay superseded as specifications. Removing candidate supersession would need its own decision and work package. The AP-06 handover and AP-13 inputs name `processing_candidates`.
- **Owner detail:** [AP-06 handover](../execution/ap-06.md#handover), [docs/architecture.md](../../docs/architecture.md)
