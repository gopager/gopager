## Implemented behavior (specified in `docs/` and OpenAPI)

- Routes and schemas: [OpenAPI v1](../../api/openapi/v1.yaml) (`info.version` 1.6.0), tags `Address rules`, `Suppressions` and `Assignment corrections`; route table, preview, correction progress and retry: [HTTP API: Address rules, suppressions, corrections](../../docs/http-api.md#address-rules-suppressions-corrections). Right scopes: [HTTP API: Authorization](../../docs/http-api.md#authorization). Matching itself has no public route; the internal ports are in [`internal/assignments`](../../internal/assignments/) and the management adapters in [`internal/httpapi`](../../internal/httpapi/).
- Rule shape, half-open validity at the Observation time, selectors per Protocol, set-subset specificity, rejection of equal or partially overlapping rules and of POCSAG mode conflicts, `assigned` and `unassigned` resolution, targetless handling, suppression semantics, original target reference `(transmissionId, targetPosition)` and the `message_units` cache: [Architecture: Address rule semantics](../../docs/architecture.md#address-rule-semantics).
- Initial admission at intake (Network resolution, target matching, cache upsert, one `assignment.changed` per Transmission): [Architecture: Intake](../../docs/architecture.md#intake-one-transaction).
- Selector-scoped correction (scope per rule version, Unit deletion or single suppressed target; assignment-revision stamps on targets; lease and fencing; batches of 100; five attempts and `correction.failed`; re-admission of Processing; `correcting` cache rows): [Architecture: Historical correction](../../docs/architecture.md#historical-correction-worker-role). Failure code `RETRY_LIMIT`: [HTTP API: Errors](../../docs/http-api.md#errors).
- Gateway mapping re-resolution (`gateway` scope per changed Protocol, stored declaration, Network move with `previousNetworkId`, unresolved flag and count, Gateway lock, Agency-wide authorization; [D-139](../decisions/02-intake-and-grouping.md#d-139), [D-141](../decisions/03-assignment-and-correction.md#d-141)): [Architecture: Historical correction](../../docs/architecture.md#historical-correction-worker-role), [HTTP API: Gateway administration](../../docs/http-api.md#gateway-administration); cases F-10e, [F-97..F-100](reference-cases.md#ap-20-gateway-mapping-re-resolution-cases).
- Network re-inference after rule changes (`gateway` scopes with reason `rule-change` for every Gateway whose mapping shares the rule's Network with another Network of the Protocol, limited to undeclared Transmissions with targets; rule-write authority unchanged; [D-143](../decisions/03-assignment-and-correction.md#d-143)): [Architecture: Historical correction](../../docs/architecture.md#historical-correction-worker-role), [HTTP API: Address rules](../../docs/http-api.md#address-rules-suppressions-corrections); case [F-101](reference-cases.md#ap-20-gateway-mapping-re-resolution-cases). A mapping replacement also needs authority over the Agencies of the Networks the Gateway's Transmissions of a changed Protocol reference (case F-102).
- Encrypted marker ([D-145](../decisions/03-assignment-and-correction.md#d-145), REQ-124): an Address rule's `encrypted` label, set by rule create and update, changes no matching, correction or Payload access and queues no correction: [HTTP API: Address rules](../../docs/http-api.md#address-rules-suppressions-corrections). Its projection on assigned targets is C-07.

Decisions that remain binding: an Address-to-Unit assignment is temporal while general Unit attributes are not; a later-entered rule valid from X corrects history using Observation time; suppression is Transmission-target specific, mixed Messages stay partly usable, a hidden assignment is not relabelled "Without Unit", and no Payload masking or implicit administrator bypass exists; matching results are internal derivations and grant no read right; a removed rule leaves no stale Unit authority; exact replay of earlier derivations is not promised and no immutable Address-rule-version entity exists; correction never writes originals, Grouping or new Transmissions; failed work stays inspectable and an authorized retry never revives superseded work; correction status and retry require coverage of every affected scope and otherwise look like an unavailable job.

## Planned and not yet implemented

- **Rematch debounce.** Rematching should start after 60 seconds of inactivity by default and further changes may not postpone the start beyond 300 seconds by default; both are configurable values and neither is a completion SLA. The runner currently claims due scopes without such a delay.
- **Delivery reuse.** Already created read or Delivery jobs may keep their original domain context; C-09 reuses it only after current access checks. No historical job is rewritten for a cosmetic edit.
- **Exchange and bulk execution location (T089, [AP-15](../work-packages/ap-15-frontend.md)).** The exchange of Units, Address rules, Suppressions and Unit collections and the bulk changes of Address rules and Suppressions are use cases in `internal/assignments/`, which imports `internal/units/` (never the reverse), and run in one transaction through the platform transaction context; collection bulk lives in `internal/units/`. They reuse the existing actions and command receipts: no new actions and no change to `internal/commands`. Defaults: at most 500 Units and 2,000 Address rules, Suppressions or collections per document, body at most 5 MiB. Each executed run that changes Address rules or Suppressions enqueues the existing selector-scoped correction once.
