## Implemented behavior (specified in docs)

The wire contract is [`api/plugin/v2/plugin.proto`](../../api/plugin/v2/plugin.proto) with the Go SDK [`pluginsdk`](../../pluginsdk/pluginsdk.go) (go-plugin over gRPC, protocol 2, UTF-8 JSON records). Everything else is in [Plugins](../../docs/plugins.md): the runtime model with one pooled process per instance revision, lazy start, `SecureConfig` digest check, idle timeout and stop rules ([§1](../../docs/plugins.md#1-runtime-model)); the invocation envelope with `instanceId` and the `mode` field `live` or `preview` ([§3](../../docs/plugins.md#3-invocation-request)); the response and the failure classification with automatic retry ([§4](../../docs/plugins.md#4-response)); all limits (call deadline, handshake, request and response size, executable size) ([§5](../../docs/plugins.md#5-limits)); the artifact directory, manifest, `configurationPolicy` with `admin` and `user` scope, digest and instance pins, `supportsPreview` ([§6](../../docs/plugins.md#6-packaging-and-installation)). Operator view: [Operations: Plugin Directory](../../docs/operations.md#plugin-directory). Typed code: [`internal/processing`](../../internal/processing/) (`installed.go`, `artifacts.go`, `plugin_runtime.go`, `instance*.go`). Management routes: [HTTP API: Processing instances](../../docs/http-api.md#processing-workflows-versions-candidates).

Decisions that remain binding:

- Operator-installed plugins are fully trusted separate executables run as application-managed child processes (D-130, D-131), one process per configured instance. The Core provides no sandbox and no memory limit; process separation isolates crashes and allows killing a hung plugin but is no security boundary. Plugins may have direct host, device and network access (GPIO, printers, MQTT, KNX and similar). In-process native loading (Go `plugin`, C-ABI libraries) is not supported. Only operators install or update code; web administrators configure permitted capabilities; users own allowed subscriptions. There is no marketplace and no native legacy ABI; any language with gRPC can implement the protocol, and only the Go SDK is supplied.
- A plugin failure cannot change another domain's data or grants or bypass attempt recording. The Core never downloads, compiles or installs plugins, and a missing artifact means capability or dependency unavailable, never a built-in stub.
- Workflow steps accept only modules that declare `pure`, require no Core fields or operations and no host capabilities; purity is the author's trusted declaration, not enforced. Preview never calls a plugin without `supportsPreview` and fails with `AUTHORITY_UNAVAILABLE` instead (no fallback), and it checks the current execution Principal, the source and the editor separately. Unresolved Secret references block activation and invocation.
- The manifest configuration contract is mandatory for the SDK and API, not optional UI metadata: every configurable property, including nested properties and collection elements, declares type, validation, required or default behavior, explicit Secret classification and a `configurationScope` (`admin` or `user`); omission, unknown scope, conflicting declarations or an unclassified open-ended property invalidate the manifest, and container replacement or merges preserve the classification so a personal write cannot bypass an administrative child. Configuration reads and writes enforce this server side, expose only permitted fields and redacted Secret status, and reject unknown or unauthorized fields atomically. Personal values never shadow administrative values, and a manifest update that changes a scope incompatibly is a visible configuration failure. C-09 owns the configuration-authority boundary. Planned cases: [F-45](reference-cases.md#ap-04-plugin-configuration-cases).
- Bytes use the canonical typed encoding of [Workflows: Typed values](../../docs/workflows.md#typed-values); an old or incompatible host, worker or module fails explicitly and never reinterprets or drops bytes. Bytes in configuration, personal and Secret schemas stay unsupported.

## Planned and not yet implemented (AP-11, AP-12)

- **Full manifest.** Offered Delivery capability, Secret field declarations and informational resource expectations (not enforced by the Core). Per-Unit values are the `integration_unit_parameters` table of [C-09](c-09-delivery.md), not manifest Extension fields ([D-135](../decisions/10-foundation-redesign.md#d-135) item 15). Event-reaction and Core-read capabilities are not implemented (REQ-139, later); a manifest declaring `requiredOperations` or `requiredCoreFields` for a Delivery capability is rejected with `CAPABILITY_UNDECLARED`. Unknown required capabilities and incompatible major versions block activation. Inspection never runs plugin initialization with active credentials. AP-12 T069 defines the generated schema and SDK configuration types.
- **Core target descriptor and attempt port (AP-11 T066, version 1, Go types in `internal/delivery`).** `TargetDescriptor`: `version` 1, `instanceId`, `instanceRevision` (configuration revision), `capabilityKind` `delivery`, `configurationAuthority` `admin` (AP-12 adds personal values), `outputKinds` (subset of `text`, `markdown`, `json`; the selected output context of the layout), typed `inputs` (unique name, scalar kind — string, boolean, integer, number, timestamp or bytes —, required, maximum bytes; a descriptor with another input declaration is invalid and its target unavailable), classified `dependencies` (kind such as `network` or `secret` and a safe description), optional `sendsPerMinute` and `idempotent`. `AttemptInvocation`: `version` 1, Delivery ID (also the provider idempotency key), attempt ID and number, instance ID and revision, the materialized input (`outputKind`, `body`, `inputs`), the triggering fact's `correlationId` and `causationId` (the Domain event ID when the fact has no causation), and the deadline. `AttemptResult`: `status` `accepted | transient | permanent | uncertain`, a safe `code`, optional `retryAfter` and a bounded (4 KiB) JSON receipt. The port is `delivery.Targets` (`Describe(instance)`, `Attempt(invocation)`); an error from `Attempt` after start is uncertain. AP-12 implements it with the plugin host; AP-11 tests use controlled providers, and production without AP-12 answers `AUTHORITY_UNAVAILABLE`.
- **Envelope additions.** SDK version, job and attempt reference, resolved Secret version, correlation reference (the triggering fact's `correlationId` and `causationId`) and the accepted, transient, permanent or uncertain result status belong to the Delivery attempt contract of AP-11 T066 and the mapping of AP-12 T069. Delivery plugins make no Core reads and there is no host-callback API; AP-12 adds only the Delivery-target capability kind. Event reactions, Core reads (through the versioned HTTP API under a technical Principal) and plugin-emitted Domain events are REQ-139, later.
- **Lifecycle.** installed, validated, configured, active, with incompatible, disabled and failed distinguishable; configuration is revisioned and checked before activation. Update validates a new artifact and configuration without mutating running invocations; existing invocations keep their digest, configuration and Secret version, and no new old-version start happens after the switch. Disable stops new starts, cancels outstanding work best-effort and records uncertain effects honestly. Rollback reactivates a still-compatible preserved artifact and configuration and never undoes external effects or silently downgrades incompatible state; a missing old artifact visibly blocks its pending work. Docker updates preserve mounted artifacts and configuration.
- **Helpers.** `pluginsdk/safehttp` is the HTTP transport used by both first-party plugins, with deadline, cancellation and size limits. `pluginsdk/plugintest` is the server-side harness that simulates the Core calling a plugin (manifest validation, configuration and Secret delivery, Delivery invocation, result mapping). First-party plugins are separate Go modules under `plugins/<name>/` tested against local fakes. Plugin status (last start, last failure code, running) is part of the instance read view; the existing pool, lazy restart and shutdown are reused without new backoff, and a node claims an instance's Delivery work only if the pinned artifact (path and digest) is loadable from its plugin directory, otherwise the attempt stays pending as `dependency-unavailable`.
- **Secrets and external transport ([D-142](../decisions/09-process-and-documentation.md#d-142)).** An in-app encrypted Secret store is mandatory: authenticated encryption (AES-256-GCM), a versioned key ID, the master key from `GOPAGER_SECRET_KEY_FILE` or `GOPAGER_SECRET_KEY`, never logged; without a key, Secret-bearing instances fail visibly with `AUTHORITY_UNAVAILABLE`. A Secret field may instead hold an optional external reference `file:<path>` (a mounted Kubernetes or Docker Secret, or files written by External Secrets Operator or Vault Agent) or `env:<NAME>`; file references are resolved per invocation, and a changed content digest is a new Secret version, while the running invocation stays pinned; environment rotation needs a process restart. There are no provider API adapters. Manifest-declared per-instance Secrets reach only that trusted plugin invocation, pinned by version and dropped afterwards; other plugins and views get neither values nor unauthorized references; logs and errors redact secrets, with no guarantee against a deliberately malicious trusted plugin. The SDK-provided transport (`pluginsdk/safehttp`, used by the first-party plugins) validates URL, host and port, the DNS results actually connected, TLS certificate and hostname, and redirects; by default it rejects loopback, private, link-local and cloud-metadata destinations and redirects; the per-instance admin field `allowPrivateDestinations` (default false) permits intended internal infrastructure; deliberately enabled redirects revalidate and do not forward credentials to a different authority. A trusted third-party plugin that does not use the SDK transport applies its own policy; that is explicit trust, not a Core SSRF guarantee.
- **Email.** The deferred email plugin supports configured SMTP with TLS and authentication and controlled status mapping, rejects CR/LF injection in header and Address fields and never builds a shell command from Payload. Public transport requires TLS; private-infrastructure exceptions are explicit operator policy. Initial first-party targets are the separate Pushover and Webhook plugins (D-33); Telegram and email follow later, and the initial Webhook capabilities are owned by [C-09](c-09-delivery.md#initial-target-capabilities).

## AP-12 Host, Manifest, Configuration and Secrets (planning before coding)

Recorded 2026-11-12 by AP-12 before coding (T069). Where it refines a planned bullet above, this section wins; the permanent documentation takes over once implemented.

- **Manifest.** Schema 2 stays; `sdkMinor` 0 or 1 (SDK 2.1 adds the Delivery capability; an unknown minor or another major is `INCOMPATIBLE_VERSION`). New member `capability`: `processing` (default when absent, the existing pure Workflow step) or `delivery`. A `delivery` manifest has `sdkMinor` 1, `pure` false or absent, `supportsPreview` false or absent, no `inputSchema`/`resultSchema`, empty `hostCapabilities`, and a `delivery` object: `outputKinds` (non-empty subset of `text`, `markdown`, `json`), `inputs` (≤ 64 entries `{name, kind, required, maxBytes}` with the scalar kinds of the AP-11 descriptor, names unique), `dependencies` (≤ 16 `{kind, description}`, kind `network | secret | device | other`), `sendsPerMinute` (0..100000, 0 = no own limit) and `idempotent`. Non-empty `requiredOperations` or `requiredCoreFields` on a `delivery` manifest is rejected with `CAPABILITY_UNDECLARED` (403, parameter `capability` = `delivery`), at inspection, at instance save and at load. Optional informational `resources` `{memoryMiB, note}` is shown by inspection and never enforced. A `processing` manifest keeps today's rules; a `delivery` object on it is `INVALID_INPUT`. Workflow steps accept only `processing` instances; Delivery targets only `delivery` instances.
- **Configuration and Secret declarations.** `secret: true` is allowed only on `string` properties that are not inside a list; containers are `secret: false`. A `user`-scoped property must be `optional` in the schema (the administrative record never holds it). The root stays `admin`. Personal values never shadow administrative ones because each property has exactly one scope; the plugin receives one merged configuration object (administrative values plus the subscriber's personal values) that conforms to `configurationSchema`.
- **Secret storage.** A Secret property's stored value is a reference string: `secret:<uuid>` (row of the encrypted in-app store), `file:<path>` or `env:<NAME>`. Writes never accept a reference inside `configuration`; they carry a separate `secrets` map from the dotted property path to `{"value": "<plaintext>"}` (encrypted into a new `secret:` row), `{"reference": "file:…" | "env:…"}` or `null` (remove; only for optional properties). A path absent from `secrets` keeps the previous revision's reference. In-app store: AES-256-GCM, 96-bit random nonce, additional data = row ID, instance ID and owner ID (empty for administrative values), key ID = `k1:` plus the first 16 hex digits of SHA-256 of the key; the 32-byte master key is base64 in `GOPAGER_SECRET_KEY_FILE` (wins) or `GOPAGER_SECRET_KEY`, never logged or echoed. Rows are immutable: a changed value is a new row and so a new Secret version, and old rows stay with the revision that references them. Without a key, saving a Secret value fails and every invocation of an instance whose configuration holds any Secret reference fails with `AUTHORITY_UNAVAILABLE`. `file:` paths are relative (forward slashes) to the operator directory `GOPAGER_SECRET_FILE_ROOT` and cannot leave it (unset: `file:` references are rejected), read per invocation (regular file ≤ 64 KiB, one trailing newline dropped), and the content digest is the Secret version. `env:` names must start with `GOPAGER_PLUGIN_SECRET_` so a configuration administrator cannot forward Core settings such as the database URL; they are read per invocation and change only with a process restart. A web administrator therefore never reaches files or variables the operator did not place for plugins. The plugin receives resolved values only in that invocation's request plus `secretVersions` (path → `secret:<row ID>`, `file:<16 hex digest>`, `env:<name>`); the host keeps no plaintext afterwards.
- **Views.** A Secret property in any view shows `secret`, `configured`, `redacted: true` and `source` (`stored | file | env`), never the value, the path or the variable name. Error messages and logs carry only safe codes.
- **Personal values.** Table `plugin_personal_configurations(instance_id, owner_id, revision, configuration, updated_at)`, key `(instance_id, owner_id)`, holding only `user`-scoped properties (Secret ones as references). The owning User writes them under `subscription.manage-own` on their own account through `GET/PUT/DELETE /api/v1/instances/{id}/personal-configuration` (command ID and expected revision as for Subscriptions); the instance must be a current, enabled `delivery` instance whose target use admits the caller, otherwise `NOT_FOUND`. An `admin` property or an unknown property in a personal write is `INVALID_INPUT` for the whole request. A personal Secret is always a stored value sealed for its owner: `file:` and `env:` references are operator-placed Secrets for administrative configuration, so a personal write offering one is `INVALID_INPUT` and the resolver refuses them for owner-bound values. Personal writes never touch administrative values or another owner's row. Deletion by owner key for AP-14: `DeleteAccountData(ctx, tx, accountID)` removes the account's personal rows and their Secret rows in the caller's transaction.
- **Target use ([D-149](../decisions/05-events-and-delivery.md#d-149), [D-160](../decisions/05-events-and-delivery.md#d-160)).** A `delivery` instance's administrative record requires `targetUse` `{everyone: bool, principalIds: [uuid, ≤ 1000 distinct]}`; a `processing` instance must not carry it. A subscriber may use the instance as a Subscription target only when `everyone` is true or its Principal ID is listed. Checked at Subscription save (`AUTHORITY_UNAVAILABLE`, status `unavailable`, as an unavailable target), at fan-out (no Delivery for that target) and at the start check (`cancelled` `authority-revoked`). Groups are not supported because the resolved authority carries none.
- **Per-Unit values (REQ-129).** `GET /api/v1/instances/{id}/unit-parameters` (page, optional `unitId`), `PUT /api/v1/instances/{id}/unit-parameters/{unitId}` (replaces the Unit's values: map of descriptor input name → typed value, validated against the descriptor's kind and `maxBytes`) and `DELETE` of the same path, under global `plugin.configure` with command ID. Keys must be inputs the current manifest declares; the instance must be a `delivery` instance and the Unit must exist (`NOT_FOUND`). Values are stored in `integration_unit_parameters` as typed values.
- **Lifecycle and status.** Installed = artifacts in the plugin directory (operator); validated = inspection succeeds; configured = saved instance revision; `active` = enabled and loadable. The instance view adds `capability`, `targetUse`, `lifecycle` (`active | disabled | incompatible | failed`, computed on read: `incompatible` for `INCOMPATIBLE_VERSION`, `failed` for any other load or configuration failure) and `status` of the answering node `{running, lastStartedAt, lastFailureAt, lastFailureCode}` with codes `start-failed`, `checksum-mismatch`, `invocation-failed`, `deadline-exceeded`. `POST /api/v1/instances/inspection` (`plugin.configure`, body `{schemaVersion: 1, main}`) verifies a manifest and executable without starting the plugin and returns its identity, capability, schemas, policy, Delivery declaration and resources. Update = a new revision with a new pin; processes of older revisions are retired on commit (running calls end and the Delivery records the uncertainty honestly), and no new start of an older revision follows. Disable = `enabled: false`, same retirement. Rollback = a new revision pinning an older, still present artifact; a missing artifact fails inspection at save and defers pending Deliveries as `dependency-unavailable`. The existing pool, lazy restart and idle timeout are reused without new backoff.
- **Delivery invocation (wire, schemaVersion 2).** Request: `{"schemaVersion": 2, "kind": "delivery", "invocationId": <attempt ID>, "instanceId", "instanceRevision": "<n>", "artifactDigest", "capabilityId", "deadline", "configuration": <merged object, Secrets resolved>, "secretVersions", "attempt": {"deliveryId", "attemptId", "attemptNumber", "subscriberId", "correlationId"?, "causationId", "outputKind", "body", "inputs": {name: typed value}}}`. A processing request has no `kind`. Response: `{"schemaVersion": 2, "attempt": {"status": "accepted | transient | permanent | uncertain", "code": "<[a-z0-9-]{1,64}>", "retryAfterSeconds"?: 0..86400, "receipt"?: <JSON ≤ 4 KiB>}}`. The host maps: a start or handshake failure before the request was sent → `transient` `plugin-unavailable`; a transport failure, deadline or malformed response after it was sent → uncertain (error); an invalid `code` → `invalid-code`; a receipt over 4 KiB, not JSON, or containing any resolved Secret value of this invocation → dropped and code `receipt-redacted`. Missing required personal values are the plugin's `permanent` `recipient-missing`. The SDK (`pluginsdk`) offers `DeliveryRequest`, `DeliveryResult` and `ServeDelivery`.
- **Placement (REQ-117).** The Delivery runner's claim filter is a function listing the current enabled `delivery` instances whose pinned manifest and executable are loadable from this node's plugin directory (cached for 5 s). Due Deliveries of those instances are claimed at once; a Delivery still unclaimed 60 s after it became due may be claimed by any node, which defers it as `retry-pending` `dependency-unavailable` (no attempt consumed) when it cannot load the artifact. Without a plugin directory the list is empty.
- **SDK helpers.** `pluginsdk/safehttp`: HTTP client that resolves the host itself, rejects loopback, private (RFC 1918, RFC 4193), link-local, CGNAT, unspecified, multicast and cloud-metadata addresses (169.254.169.254, fd00:ec2::254) of every resolved address and dials the checked address, rejects ports below 1024 other than 80 and 443, verifies TLS with the URL host, refuses redirects unless enabled (then at most 3, no HTTPS-to-HTTP downgrade, each hop revalidated, `Authorization` and caller-named sensitive headers dropped on an authority change), bounds response bodies and reports whether the request was fully written; `AllowPrivate` (the instance's `allowPrivateDestinations`) lifts only the address and port rules. `pluginsdk/plugintest`: builds or takes a plugin executable, writes a temporary plugin directory and manifest with the real digest, validates the manifest with the Core's rules, delivers configuration, personal values and Secrets, invokes a Delivery attempt through the Core's host and returns the mapped result.
- **Packaging.** `plugins/pushover` and `plugins/webhook` are separate Go modules (`replace` to the repository root), each with `manifest.template.json` whose digest placeholder the build fills. `make plugins` builds them into `build/plugins/<id>/<version>/`; `make` and `make test` run their tests and `make lint` their format and vet checks. The compose image copies both into `/usr/lib/gopager/plugins` and sets `GOPAGER_PROCESSING_ARTIFACT_ROOT` to it.
