## Implemented behavior (specified in `docs/`)

Exact canonical-identity matching across Protocols, Gateways and Networks; the inclusive whole-second window (range, default, `0` disabling Grouping); the chain rule; no maximum Message age and no lateness cut-off; merge into the lowest ID without aliases; policy changes not regrouping existing Messages; Message time; per-identity serialization and atomic commit with the facts: [Architecture: Grouping rules](../../docs/architecture.md#grouping-rules) and [Architecture: Intake](../../docs/architecture.md#intake-one-transaction). Membership facts: [Architecture: Domain events and outbox](../../docs/architecture.md#domain-events-and-outbox). Decision code: [`internal/messages`](../../internal/messages/).

Decisions that remain binding: the Gateway never submits membership and may not deduplicate or merge Transmissions to extend a Message; transport retries do not extend the window; one shared Grouping policy does not assert a common real-world incident; Message and Transmission references may be replaced on merge (D-40), an invalidated reference is `NOT_FOUND` and read models reconcile.

## Planned and not yet implemented

- **Grouping policy management (AP-10 or the owning management AP).** `GetGroupingPolicy(context, Principal) -> W, policyRevision` and `ChangeGroupingPolicy(context, Principal, expectedRevision, W) -> newPolicyRevision` have no HTTP route yet. A change needs the grantable `grouping.configure` action at `all` scope, commits value, revision and audit record atomically, applies to decisions that capture the new revision afterwards, and audits old and new values. There is no per-Message policy pinning and no Address-rule-version entity.
- **Representative selection.** No mandatory second original copy. The display Payload of a Message is chosen among usable readable exact members: prefer members not marked incomplete, then the earliest Acceptance time, then the ascending Transmission reference; otherwise the same tie-break with a visibly qualified fallback; repeat within readable evidence when the stored preference is inaccessible. No longest-text assumption, concatenation or synthetic completion; a canonically different fuller text stays another Message. A better representative within the same identity changes display, not Unit first times. The semantic reference name is `representativeTransmissionId`. C-07 consumes it.
- **Projection.** Global last-Transmission time, Message size and Gateway list are not automatically visible; Query projects from permitted Transmissions and hidden Transmissions must not leak through counts, ordering or change indicators.
- **Controlled historical regrouping.** Recomputing Grouping from retained originals under another policy is an architectural possibility, not a requirement or promised operation (D-39/D-40); no split or rebuild machinery is authorized. Before it could be approved, the owning contracts would have to define consistent replacement publication with concurrent intake and corrections, fencing, `message_units` reconstruction, safe query and live resynchronization, pending job references and whole-Message retention; historical reprocessing suppresses external reactions by default, so regrouping is no permission for duplicate Delivery. No old-to-new ID mapping is reserved.
- **Comparison extension.** C-02 owns comparison; this contract consumes exact match results. A future non-exact comparator needs explicit approval of candidate discovery, temporal constraints, re-evaluation, split and reference events, Delivery semantics and concurrency.
