## Implemented behavior (specified in `docs/` and OpenAPI)

Routes and schemas: [OpenAPI v1](../../api/openapi/v1.yaml) (`info.version` 1.9.0), tags `Agencies`, `Organizations`, `Unit templates`, `Units` and `Unit collections`. Semantics: [HTTP API: Agencies, Organizations, Unit templates, Units, collections](../../docs/http-api.md#agencies-organizations-unit-templates-units-collections) and [Master data semantics](../../docs/http-api.md#master-data-semantics) (Unit identity, exactly one Agency, collection membership, `inherit`/`value`/`unset` settings, color, icon and Function-meaning rules, name limit, templates as copied snapshots, Organization deletion with materialized defaults and no Rematch, Unit deletion marker and pending correction, bulk operations with their 100-item limit, required rights). Authorization of these routes: [HTTP API: Authorization](../../docs/http-api.md#authorization). Correction after Unit deletion: [Architecture: Historical correction](../../docs/architecture.md#historical-correction-worker-role). Typed code: [`internal/units`](../../internal/units/).

Decisions that remain binding: formation membership alone is not evidence of co-alerting and there is no unrestricted multi-parent default graph; a Unit is not subordinate to a Network; no historical color or icon versioning is needed for general master data; conflict details never reveal hidden uses elsewhere; a concurrent Organization and Unit edit conflicts instead of losing a value.

## Planned and not yet implemented

- **Extension fields.** Dropped by [D-135](../decisions/10-foundation-redesign.md#d-135): per-Unit integration values use the per-integration parameter table owned by [C-09](c-09-delivery.md) (AP-11, AP-12). Administrator-defined Unit attributes (below) are a separate concept with no plugin namespace and no rights effect.
- **Unit attributes (REQ-142, [D-150](../decisions/04-processing-and-plugins.md#d-150), [AP-22](../work-packages/ap-22-unit-attributes.md)).** A Unit carries values of `unit` Attribute schemas ([C-11](c-11-processing-presentation.md#attribute-schemas-and-agency-binding-planned)) that are assigned to its Agency ([D-151](../decisions/06-identity-and-authorization.md#d-151)). Each value uses the setting modes `inherit | value | unset`: `inherit` resolves to the Organization's default, Organization deletion materializes still-inherited values, and templates copy effective values, exactly as for the settings in [HTTP API: Master data semantics](../../docs/http-api.md#master-data-semantics). Changing a Unit's Agency requires removing the values of schemas that are not assigned to the new Agency. Edits need `unit.update` (Organization defaults: `organization.update`); they never change rights, never reprocess Messages and are no correction work.
- **Agency deletion and definitions ([D-151](../decisions/06-identity-and-authorization.md#d-151), [AP-21](../work-packages/ap-21-attribute-schemas.md)).** An Agency that is the last assigned Agency of a Workflow, Layout or Attribute schema cannot be deleted (`409 REVISION_CONFLICT`); otherwise its definition assignments are removed together with it.
  AP-21 binding (2026-11-11): Implemented by AP-21 ([handover](../execution/ap-21.md#handover)). `unitstore.DeleteAgency` checks, under the Agency's row lock, whether an undeleted Workflow, a Layout or an Attribute schema has this Agency as its only assigned Agency (`units.ErrAgencyInUse`, `409 REVISION_CONFLICT`); the assignment rows of other definitions and of soft-deleted Workflows cascade.
- **Icon catalog and renderer.** The server stores and copies an icon identifier only. [AP-15](../work-packages/ap-15-frontend.md) (T079/T080) defines the identifier set from a bundled open-licensed icon set chosen under [D-36](../decisions/01-platform-and-storage.md#d-36), the renderer, and the fallback for an unknown identifier (an accessible label, never color alone), and records the result here replacing this line. Unit and Organization color and icon render consistently in management and Message views (REQ-022).
- **Exchange and bulk (REQ-128, REQ-140).** Server-to-server exchange of Units with their Address rules, Suppressions and Unit collections, and bulk changes of collections, are planned and implemented by [AP-15 T089](../work-packages/ap-15-frontend.md#planning-before-coding) ([D-138](../decisions/09-process-and-documentation.md#d-138)); the exchange document and bulk rules are defined here and in [C-05](c-05-matching-correction.md) by that task.
