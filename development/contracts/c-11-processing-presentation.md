## Implemented behavior (specified in `docs/` and OpenAPI)

Routes and schemas: [OpenAPI v1](../../api/openapi/v1.yaml) (`info.version` 1.7.0), tags `Workflows` and `Processing instances`; route table and rights: [HTTP API: Processing](../../docs/http-api.md#processing-workflows-versions-candidates) and [Processing: plugin instances](../../docs/http-api.md#processing-plugin-instances). Semantics, all in [Workflows](../../docs/workflows.md): definition format, selector, steps (map, Core RE2 extract, branch, installed), field schema and typed values ([Definition format](../../docs/workflows.md#definition-format)); predicates and bounds ([Predicates](../../docs/workflows.md#predicates)); result shape with `fields` or `targetResults`, one run per Transmission and Workflow, namespaces that never overwrite another Workflow's fields ([Result shape](../../docs/workflows.md#result-shape)); one classification per definition version, applied at projection ([Classification](../../docs/workflows.md#classification)); save-time validation against the author's readable field groups ([Validation](../../docs/workflows.md#validation)); lifecycle, versions, atomic activation and previous-version selection, no automatic historical sweep ([Lifecycle](../../docs/workflows.md#lifecycle)); preview without live writes, events or external effects ([Preview](../../docs/workflows.md#preview)); admission, dispatch, candidate states, retries, stale-work supersession, publication and `processing.completed` ([From transmission to candidate](../../docs/workflows.md#from-transmission-to-candidate) to [Events](../../docs/workflows.md#events)); status reads and the processing status `none | pending | completed | failed` without a publication barrier ([Status reads](../../docs/workflows.md#status-reads), [Architecture: Processing status](../../docs/architecture.md#processing-status)); limits ([Limits and defaults](../../docs/workflows.md#limits-and-defaults)). Typed code: [`internal/processing`](../../internal/processing/).

Decisions that remain binding: no arbitrary inline scripts, loops or expanded permissions; saving and taking effect are distinct without a mandated multistage approval; concurrent edits conflict instead of overwriting; original Payload is preserved and processing or presentation version changes create no Transmission and no regrouping; derived fields keep their classification and extraction does not make hidden text public; installed code receives only its declared authorized input under the configured execution Principal, never the editor's temporary rights, and a missing execution authority is an explicit failed or pending state; a failed Workflow leaves the status `failed` with authorized retry and never substitutes raw text; the Core regex is Go RE2 with deterministic admission bounds (D-129) and an inadmissible pattern is `RESOURCE_LIMIT`.

## Presentation and Configuration (planned)

- **Layout definition (REQ-094, D-135).** GUI cards and Delivery renderings share one declarative, versioned layout definition with the blocks `text`, `field`, `chip`, `link` (URL template), `section`, `conditional` (the C-09 typed predicate) and `fallback`, rendered by the frontend and by the Core, never as raw HTML and without a template engine ([D-135](../decisions/10-foundation-redesign.md#d-135)). A definition has ID, revision, immutable version, applicable permitted scope, typed field bindings and an output kind (GUI card or Delivery text or structured input). AP-11 implements the declarative block renderer, the validator, persisted `layout_definitions` with `presentation.manage` CRUD and the Subscription layout reference, AP-13 the GUI card adapter, the card model and editor metadata and AP-15 the editor; rendering is bounded by the shared output, nesting and collection limits and escapes interpolation for its output context.
- **AP-11 layout binding (planning before coding, 2026-11-09).** Layout 1.0: `{"schemaVersion": 1, "outputKind": "text" | "markdown" | "json", "blocks": [...]}`. Blocks: `text` (`text` literal), `field` (`field` reference, optional `label`), `chip` (`field`, optional `label`), `link` (`label`, `url` template with `{0}`..`{9}` placeholders and a `fields` list; values are percent-encoded, the expanded URL must be `https`, `http` or `mailto`, else the link is omitted), `section` (optional `title`, `blocks`), `conditional` (`when` typed predicate, `then`, optional `else`), `fallback` (`blocks`: the first alternative that renders non-empty). Field references use the Delivery field catalog of [C-09](c-09-delivery.md#ap-11-core-binding-planning-before-coding); an absent field renders nothing. Bounds: 256 blocks, nesting 8, literal 4 KiB, output 64 KiB (`RESOURCE_LIMIT` at save, `render-limit` at materialization). Output: `text` writes plain lines with control characters other than newline removed; `markdown` escapes Markdown metacharacters in every interpolated value; `json` emits an ordered array of `{kind, label, value | text | url | items}` objects with typed values. Values format as: string verbatim, numbers in decimal, booleans `true`/`false`, timestamps RFC 3339 UTC, bytes canonical Base64, lists comma-separated, objects compact JSON. No HTML output, no template engine. Persistence: `layout_definitions` (ID, revision, name, output kind) with immutable `layout_definition_versions` (layout, version = revision, definition); routes `GET/POST /layouts`, `GET/PUT/DELETE /layouts/{id}`, `GET /layouts/{id}/versions/{version}` with `presentation.manage` (scope `all`) for writes, readable also for `subscription.manage-own` and `subscription.manage-global` holders; a referenced layout cannot be deleted (`409 REVISION_CONFLICT`). `processing.LayoutResolver` returns the Subscription's layout at its current version, otherwise the built-in default of the requested output kind (version 0); the Delivery records the layout ID and version it rendered. Saving a layout checks only structure; field rights are checked when a Subscription references it.
- **Safe output.** GUI card models support text, labeled structured sections, icons, links and buttons, and configured map references. Missing permitted location fields fall back to permitted original text under explicit conditions, never hidden alternate evidence. No browser script or untrusted HTML; icons are sanitized, unsafe URL schemes and event handlers are rejected. Administrator-defined external links and maps may deliberately transmit permitted parameters (D-25) and their external origin is visible. A preview makes no outbound request.
- **Precedence** is fieldwise: installation default, then Organization, then Unit, then Subscription. AP-11's resolver knows the Subscription layout and a built-in default; AP-13 binds the installation default (in `installation_settings`) and the Organization and Unit assignments (table `layout_assignments`, no change to C-04) into it. Conflicting whole layouts from several Units are resolved by explicit choice or separately scoped sections, never by iteration order or by combining hidden Unit settings. Personal formatting preferences never widen field rights or alter source results.
- **Displayed source.** GUI rendering consumes the readable exact Representative Transmission of [C-03](c-03-message-grouping.md), never a global text or concatenated originals; a restricted view's fallback never inherits fields derived only from hidden evidence; presentation uses the Representative Transmission and shows that Transmission's completed results or its `processing_status`, never results derived from another member.
- **Installation banner ([D-135](../decisions/10-foundation-redesign.md#d-135) item 15).** Installation title and banner are one revisioned `installation_settings` row: title, optional plain-text banner, optional severity and the default layout reference. It is edited with `notice.manage` and `expectedRevision` through `GET/PUT /api/v1/installation` (read is public, including guests) and shown to everyone while set; there is no dismissal, no notice ID and no audience.
- **Preferences ([D-142](../decisions/09-process-and-documentation.md#d-142)).** Account preferences are the formatting locale, the IANA time zone and the time-gap threshold in minutes (0 turns it off, range 0..1440), with ordinary revision checks under the action `preference.manage-own`; there are no Delivery defaults here (Delivery configuration stays in C-09). Invalid locale or time zone input is explained, never silently replaced; the UI language is English initially. Text, touch and keyboard operation, states readable without color and context-preserving copy and details are frontend acceptance goals.

## Historical Reprocess (planned)

`Reprocess` (action `workflow.reprocess`) with a scope of the Workflow selection scope (all, network or unit) intersected with an explicit Message-time range and the chosen version is not implemented; `workflow.reprocess` is authorized over the Unit and Agency scopes of the affected Transmissions and the stable scan cutoff is the maximum accepted Transmission sequence at request time; the retry of a single failed candidate is. It uses current access and target state, preserves original Payload and membership, publishes replacement results atomically after success, and never keeps a result visible merely because it existed once if the source authority is invalidated. Reprocess publishes `processing.completed` with `replayMode` `reprocess`, which suppresses automatic Delivery fan-out (AP-11 owns the vocabulary in C-08); redelivery is C-09's separately confirmed operation. AP-13 owns it.

## Text-key Mapping and Remaining Technical Evidence

The implemented API error-code and fallback table is [HTTP API: Errors](../../docs/http-api.md#errors); [C-07](c-07-query-live.md) lists the codes still to be added. C-11 owns `status.<status>`, `validation.<constraint>`, `processing.<reason>` and component/action/accessibility keys. Registry entries require an English base string, typed named parameters and plural forms when count-dependent; CI in AP-15 checks every referenced built-in key/parameter against the catalog. Validation constraints reuse shared names (`required`, `type`, `range`, `maxLength`, `pattern`, `reference`, `cycle`); processing reasons include `no-match`, `conversion-failed`, `capability-unavailable`, `resource-limit` and `evaluation-failed`. Missing optional output is not displayed as failure.

A missing translation uses the English entry; a missing key/invalid parameter emits a redacted diagnostic and safe generic English text, never the confidential raw argument or an untranslated key. New built-in status/constraint/reason values require their English entry in the same change. Trusted operator templates and received data are not automatically translated. Exact component wording, the Vue i18n library and editor controls are AP-15 implementation artifacts, not a requirement for another locale.

| Text keys (one entry per listed suffix) | English base entries, in the same order |
| --- | --- |
| `status.pending`, `.running`, `.completed`, `.failed`, `.superseded` | Pending; Running; Completed; Failed; Superseded |
| `status.prepared`, `.started`, `.retry-pending`, `.accepted`, `.expired`, `.cancelled`, `.uncertain`, `.dependency-unavailable` | Prepared; Started; Retry pending; Accepted by provider; Expired; Cancelled; External outcome uncertain; Required data unavailable |
| `status.never-seen`, `.active`, `.degraded`, `.stopped`, `.contact-lost` | Never contacted; Active; Degraded; Deliberately stopped; Contact lost |
| `status.installed`, `.validated`, `.configured`, `.incompatible`, `.disabled` | Installed; Validated; Configured; Incompatible; Disabled |
| `status.deleting`, `.cleanup-failed`, `.retrying`, `.fresh`, `.processing-pending`, `.resync-required` | Deleting account; Account cleanup failed; Retrying; Up to date; Processing pending; Reload required |
| `validation.required`, `.type`, `.range`, `.maxLength`, `.pattern`, `.reference`, `.cycle` | Required value missing; Invalid value type; Value outside allowed range; Value exceeds length limit; Unsupported or invalid pattern; Invalid reference; Cyclic references are not permitted |
| `processing.no-match`, `.conversion-failed`, `.capability-unavailable`, `.resource-limit`, `.evaluation-failed` | No matching value; Value conversion failed; Capability unavailable; Processing limit exceeded; Processing failed |
| `account.deleted`, `delivery.retryPending`, `history.retainedPartially`, `workflow.failed` | Deleted user; Retry pending; Earlier history may have been removed; Workflow failed |

`account.deleted` carries the distinguishing suffix separately; add it accessibly without turning an ID into a name. `status.accepted` is scoped to Delivery; intake acknowledgement uses its own component wording, never claims provider acceptance. Validation parameters are typed `field`, `constraint`, `limit` as applicable. Count-dependent component keys declare an integer `count` and English singular/other forms (for example `{count} item` / `{count} items`), not concatenated fragments. Component/action labels are populated with their implementing UI, not a speculative catalog of screens.
