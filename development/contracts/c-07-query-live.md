## Implemented behavior (specified in `docs/` and OpenAPI)

The HTTP error envelope, code table with status and `retryable`, retry semantics of `REVISION_CONFLICT`, the `RETRY_LIMIT` correction failure code, the safe `fallback` texts and `textKey` mapping, and the shared list and paging conventions of the management routes: [HTTP API: Errors](../../docs/http-api.md#errors), [Conventions](../../docs/http-api.md#conventions) and the `Error` schema of [OpenAPI v1](../../api/openapi/v1.yaml) (`info.version` 1.7.0). Platform failure classification and the PostgreSQL SQLSTATE mapping: [Architecture: Errors and failure codes](../../docs/architecture.md#errors-and-failure-codes).

AP-10 Query, live and saved views (implemented 2026-11-08, [AP-10 record](../execution/ap-10.md#handover)): appearance eligibility, field groups, filters, PostgreSQL text search, order, HMAC keyset page token, snapshot cutoff `position`, projections (Representative Transmission, Unit summaries, encrypted label, correction and processing status, target resolutions, derived results, `networkUnresolved`) and filter options: [HTTP API: Messages: query and detail](../../docs/http-api.md#messages-query-and-detail); positions, frames, fact handling, bounds, replay window and resync: [Messages: live stream](../../docs/http-api.md#messages-live-stream); [Saved views](../../docs/http-api.md#saved-views); [Search rate limiting](../../docs/http-api.md#search-rate-limiting); keyset paging: [Pagination](../../docs/http-api.md#pagination); data flow: [Architecture: Query](../../docs/architecture.md#query-api-role); flags `--search-attempts-per-minute`, `--live-replay-window`: [Operations](../../docs/operations.md#configuration-reference). Cases: [AP-10 query and live cases](reference-cases.md#ap-10-query-and-live-cases).

Binding rules for every response: codes are stable and language independent; Product-generated outcomes carry `error.<CODE>` or `status.<status>` text keys with a redacted English fallback and structured parameters; no client parses prose; UI language and formatting locale change no ID, field name, enum, timestamp, token or authorization outcome; invisible, deleted or invalidated references share one `NOT_FOUND` shape and never expose a replacement ID.

## Planned and not yet implemented

**Selection predicate and attributes ([D-152](../decisions/07-query-and-live.md#d-152), [D-150](../decisions/04-processing-and-plugins.md#d-150), [AP-21](../work-packages/ap-21-attribute-schemas.md)):** Feed, live stream and saved views accept a `filter` holding the typed predicate of [C-09](c-09-delivery.md#typed-predicates-and-values-implemented) over field-registry fields, compiled to SQL; the simple filter parameters stay, the `derived` parameter is removed, and a saved-view `definition` stores the predicate. Message attributes are addressed as `attributes.<schemaKey>.<field>[.<property>…]` and match the effective value of any target position the caller may see; Unit attributes ([AP-22](../work-packages/ap-22-unit-attributes.md)) as `unit.attributes.<schemaKey>.<field>…` and match on the Message's eligible Unit appearances, correlated with the same appearance like the other Unit dimensions (REQ-029). Only paths to scalars and lists of scalars are filterable (any-element semantics). An unknown field or a non-filterable path is `INVALID_INPUT`, and a predicate needing an unreadable field group is rejected as the `derived` filter is today (REQ-017). Projections show the effective Message attributes with their provenance (`workflowId`, `definitionVersionId`, `resultId`) and the Unit attributes. A typed projection table of effective values is added only when AP-21's measurement shows the gain.

**AP-11 (planning before coding):** Delivery uses the read side under the subscriber's resolved authority inside the consumer or runner transaction (`readmodel.Service.ProjectForDelivery`), with the same eligibility, field groups and readable result versions as the feed, plus the per-Unit first observations needed for Delivery age anchors; it adds `DEPENDENCY_UNAVAILABLE` (redelivery after the original input ceiling) and `EXTERNAL_UNCERTAIN` (retry of an uncertain Delivery). `CAPABILITY_UNDECLARED` stays with AP-12.

**Error codes:** `DEPENDENCY_UNAVAILABLE` (parameter `dependency`) and `EXTERNAL_UNCERTAIN` (parameter `deliveryId`) are implemented by AP-11 ([HTTP API: Errors](../../docs/http-api.md#errors)). Not implemented yet: `CAPABILITY_UNDECLARED` (403, permitted capability name), added by AP-12 together with its English fallback text and parameters. Plugin handshake and transport failures are `DEPENDENCY_UNAVAILABLE` and a crash is `INTERNAL_ERROR` once the plugin host maps them. Outcome statuses map to `status.<status>`. C-11 owns the text-key registry. Resync is the live `resync-required` event, not an HTTP error code.
