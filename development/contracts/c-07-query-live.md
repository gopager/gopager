## Implemented behavior (specified in `docs/` and OpenAPI)

The HTTP error envelope, code table with status and `retryable`, retry semantics of `REVISION_CONFLICT`, the `RETRY_LIMIT` correction failure code, the safe `fallback` texts and `textKey` mapping, and the shared list and paging conventions of the management routes: [HTTP API: Errors](../../docs/http-api.md#errors), [Conventions](../../docs/http-api.md#conventions) and the `Error` schema of [OpenAPI v1](../../api/openapi/v1.yaml) (`info.version` 1.2.0). Platform failure classification and the PostgreSQL SQLSTATE mapping: [Architecture: Errors and failure codes](../../docs/architecture.md#errors-and-failure-codes). No Message query, detail, search or live route exists yet, so OpenAPI has no Query entry.

Binding rules for every response: codes are stable and language independent; Product-generated outcomes carry `error.<CODE>` or `status.<status>` text keys with a redacted English fallback and structured parameters; no client parses prose; UI language and formatting locale change no ID, field name, enum, timestamp, token or authorization outcome; invisible, deleted or invalidated references share one `NOT_FOUND` shape and never expose a replacement ID.

C-11 owns the text-key registry.

**Query semantics.** OR within a dimension, AND between dimensions on the same permitted `message_units` appearance (direct Unit): Agency A on one appearance cannot combine with Unit B only found on another. "Without Unit" requires proven unassigned or targetless authorized evidence, never hidden or failed resolution. Normal Message queries accept no Gateway filter. Beneficiary-controlled filter fields and operators are validated against readable, supported declarations; a hidden-field filter is explicitly unavailable, never silently dropped, translated into an unrestricted query or evaluated in a way that discloses a match, and a saved view does not bypass that eligibility. No arbitrary metric or result filter language exists.

**Projection before result formation.** Suppression, current grants and field permissions apply before filtering, counting, pagination and details. Invisible targets affect no name, count, time anchor, sorting, facet or change indicator. Message evidence grants no access to other targets; permitted detail actions may prefill Addresses; the compact list carries no blanket management action.

**Time and one row per Message (D-135 decision 9).** Feed ordering and the time filter use the stored Message time, the earliest observation of any member. Per-Unit first-appearance times stay in the details. Age limits use the per-(Message, Unit) `age_anchor` of [Architecture: Address rule semantics](../../docs/architecture.md#address-rule-semantics) and the rule of [HTTP API: Authorization](../../docs/http-api.md#authorization). A query selects the permitted appearances that satisfy all non-time filters on the same appearance, applies the permitted age, then literal Payload search on readable Payload only, and returns exactly one row per Message with its Message time; the order is descending `(Message time, Message ID)`. A later repeat for a Unit never moves the row; a new Unit appearance, older late evidence, a changed filter or permission, a correction or a merge can change the result and is reconciled by SSE (removal, replacement or resync when IDs changed). The time interval is `[from, until)`.

**Targetless evidence** has no synthetic Address or Unit; its without-Unit appearance exists for Network-authorized `without-unit.read` and uses the earliest permitted Observation time. Hidden evidence affects no counts, time, sort, facets or SSE indicators.

**Displayed Payload.** The Representative Transmission of [C-03](c-03-message-grouping.md) readable in this view; search may match another readable representation of the same canonical value and the details name that permitted source. A global representative never exposes hidden text or derived fields. Row projection contains Message ID, Message time, permitted matching target and Unit summaries and the allowed Payload and derived fields; external serialization is owned by AP-10 in OpenAPI.

**Administrative reception diagnostics.** Gateway, Network, time and Address filters apply to actual linked Transmission evidence, use each receipt's Observation time, may show every reception and are separate from the one-row-per-Message feed. They are coverage and quality evidence, not proof of an Emission nobody observed or of device reception.

**Text search.** Literal substrings, case-insensitive, accent-sensitive. The derived search value and the query are both NFC, full default Unicode casefold, then NFC (`Straße` matches `STRASSE`; composed and decomposed `é` match; `é` does not match `e`). `%`, `_` and `.*` are ordinary characters; empty text applies no filter; invalid UTF-8 is rejected. Normalized values are built once per evidence or relevant processing revision with one pinned Unicode-data version, rebuilt when it changes. Short queries stay correct without an external search engine.

**Pagination (D-135 decision 9).** Request: filters, `pageSize`, optional `pageToken`; response: `items`, optional `nextPageToken`, safe freshness, optional authorized total. The token is a stateless keyset token: an HMAC-signed value carrying the last `(Message time, Message ID)`, a hash of the normalized filters and the Principal or key restriction. It stores nothing server side, conveys no permission and exposes no hidden sort value. A token for different filters or another Principal is `INVALID_INPUT`. Because the order is descending, new data lands above the cursor and does not disturb downward paging. A page never returns a partial or duplicate Message; no offset paging and no public global revision counter or hidden-change count. Page defaults and maximum follow the management routes (see the HTTP API page).

**Live updates (SSE).** `text/event-stream`, UTF-8; `id` is the event sequence of the `domain_events` log and the client resumes with `Last-Event-ID`, replayed within the retention window, otherwise `resync-required`. Frames carry a permitted `upsert` projection, a `remove` of an already-known ID or `resync-required` without private fields. The stream carries the client's loaded Message-time range and the page's event sequence, and the server filters pushed events by the Message time they carry, so every loaded Message stays current without a live-age window (REQ-005). Initial page and stream share a consistent cutoff so no commit vanishes between them; on resync the client atomically replaces its loaded ID set and removes revoked, deleted and merged entries. Access is rechecked for every output batch, a revoked session or stale permission stops private output, and resume never proves unchanged permissions. A heartbeat every 15 s carries no private data; the work for one output batch is bounded to 30 s. The per-connection queue holds at most 256 frames or 1 MiB; a slow consumer gets a safe resync or close, never silent frame loss or an unbounded queue. Multiple tabs and shared IPs are supported within per-Principal limits. These planned bounds move to `docs/http-api.md` when AP-10 implements them.
