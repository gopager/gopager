# Reference Cases and Acceptance Preparation

[Contract index](../domain-contracts.md) | [Shared conventions](shared-conventions.md)

Referenced contracts (follow only when relevant): [C-01](c-01-transmission-acceptance.md), [C-02](c-02-protocol-payload.md), [C-03](c-03-message-grouping.md).

These are planned tests/decision examples, not executed tests. AP-01/AP-02 complete concrete inputs/expected outputs for open cases; AP-03 checks backend/runtime behavior. An unresolved outcome is not a passing case. F-01..F-25 are preserved; F-26 adds the explicit language/i18n requirement.

[AP-02 boundary cases F-27..F-41](ap-02-boundary-cases.md) cover concrete configuration, authorization, Processing, Delivery, deletion and operations transitions without expanding this core case table.

| Case | Input / situation | Expected result or explicitly open decision |
| --- | --- | --- |
| F-01 | Same Gateway and Submission ID repeated with identical content; then the same ID with a different Payload; then a retry after the Transmission was deleted by retention | The identical retry returns the existing receipt/Transmission, emits no second Transmission Domain event, and does not extend a Message. The changed content is rejected as a conflict (error code, Operational Domain event) and never overwrites the accepted Transmission. The retry after retention deletion is accepted as a new Transmission (accepted residual risk, C-01, F-23). |
| F-01a | Observation times `2026-10-25T12:00:00+01:00`, `2026-10-25T11:00:00.000Z`, `2026-10-25T12:00:00` (no offset), a missing time, and a time 1 h ahead of server time | The first two are the same instant and compare equal. No offset and missing time: the Submission is rejected as a whole with an error code, nothing is stored as Transmission, an Operational log entry is written, and an Operational Domain event is emitted. The future time is accepted, grouped normally, marked `observation-time-implausible`, logged, and emits an Operational Domain event. |
| F-01b | Gateway G assigned to POCSAG Networks N1 and N2, with Gateway Network identifier `a` mapped to N1: Submissions declaring `a`, declaring unmapped `z`, without declaration where only N2 has an Address rule for the RIC, and without declaration where both or neither have one; Gateway H assigned only to N1 without declaration | `a` resolves to N1 (`declared`); `z` is rejected with an Operational Domain event. The Address case resolves to N2 (`inferred-address`). With N1 configured as default Network: neither resolves to N1 (`default`), no Operational Domain event; both resolves to N1 (`default`) with an ambiguous-Network Operational Domain event; a later Address-rule or mapping change re-resolves through Rematching. Configuring G with N1 and N2 but no default Network is rejected. H resolves to N1 (`inferred-single`). |
| F-01c | Unknown Protocol; `numeric` Payload containing letters outside the numeric character set; a valid Submission whose Gateway is not assigned to any Network of its Protocol | Each is rejected as a whole with a stable error code and an Operational Domain event without Payload content; no Transmission is created. |
| F-02 | Same Payload submitted as a distinct independent Transmission with a distinct operation ID | The server creates separate Transmission evidence, compares Payload, and may add the Transmission to a Message under the selected policy. The Gateway submits both Transmissions independently and does not decide equality or Message membership. A transport retry is not an independent Transmission. |
| F-03 | Same Payload form and value from two authorized Gateways/Networks, with different Transmission targets | The server may perform Grouping to link the Transmissions into one Message across Gateways/Networks while retaining both Transmission/Network references and each Transmission's Transmission targets. The server—not either Gateway—determines Payload equality and Message membership. |
| F-04 | Identical alphanumeric text via POCSAG and FLEX; POCSAG address-only Transmission and FLEX tone-only Transmission; POCSAG numeric "123" and FLEX numeric "123"; numeric "123" vs text "123"; ZVEI vs POCSAG | Text/text, tone-only/tone-only, and numeric/numeric match across POCSAG and FLEX (same canonical form and value). Numeric never matches text. ZVEI has no shared form with POCSAG and cannot form a Message with it. |
| F-05 | Identical Payload with reported Observation instants t0, t0+25 s, and t0+50 s (`W` = 30 s default); timestamps include UTC offsets or the UTC designator | Grouping compares the reported instants, normalizing offsets; server acceptance times do not affect the result. Each gap is within `W`, so all three join one Message although t0+50 s is more than `W` after t0 (sliding window, no fixed expiry from t0). |
| F-06 | Matching Transmission exactly `W` (30 s) after the nearest member, and another 30 s + 1 ms after it | Inclusive boundary: exactly `W` joins the Message; beyond `W` starts a new Message. |
| F-07 | Messages G1 (member at 0 s) and G2 (member at 50 s) exist with `W` = 30 s; then a late Transmission at 25 s; separately, a Transmission reported two years in the past linking to a retained Message | 25 s links both; G1 survives by earliest first member, G2 aliases it. Equal first instants tie-break creation time then stable ID. One merge fact and the new member's joined fact commit together (C-08), without a new created fact. Result equals 0/25/50 order. A two-year-old observation can link retained evidence; no lateness cut-off. |
| F-07a | Identical Payload observed every 20 s from t0 to t0+600 s; and the same with `W` = 0 | With `W` = 30 s all Transmissions form one Message (no maximum Message age). With `W` = 0 every Transmission is its own Message. |
| F-07b | `W` is reduced from 30 s to 10 s while a Message contains members at 0 s and 25 s; then a new Transmission at 35 s; separately, a Message A (member at 0 s) and B (member at 20 s) exist under `W` = 10 s, then `W` is raised to 30 s | v1: the existing Message is not split or recomputed. 35 s is 10 s from 25 s and joins under the new revision. After raising `W`, A and B are not merged by the change itself; they merge only if a later Transmission links to both. Regrouping on configuration change is a later investigation item. |
| F-08 | POCSAG/FLEX: text "abc" to RIC B Function a, RIC C Function b, RIC D as subaddress; two empty tone-only calls to different RICs; the same text with trailing EOT/padding or CRLF vs LF | One Payload identity with three Transmission targets; Function/subaddress are Transmission target attributes resolved by Address filters. The two empty calls are Payload-identical and join one Message under normal rules. Terminators/padding are removed by the Gateway adapter; CRLF and LF compare equal; original Payload is preserved. |
| F-08a | POCSAG alphanumeric with DIN 66003 `[` from a Gateway configured for the German variant and the same text with `Ä` from a FLEX Gateway; POCSAG numeric codes `1 2 B` and FLEX numeric codes `1 2 B`; two FLEX `binary` Transmissions with equal bytes but subtypes `transparent` and `secure` | The POCSAG Gateway adapter submits `Ä`, so both texts are Payload-identical. Both numeric Transmissions are submitted as `12U` and match. The binary Transmissions differ by subtype and do not match; neither is displayed as text. |
| F-09 | ZVEI sequences 12345 and 67890 without double tone; 12345 with double tone "X" and 67890 with double tone "X"; 12345 with "X" vs "Y" | Sequences are Transmission target Addresses. Transmissions with "no double tone" are Payload-identical across Addresses; Transmissions with "X" are also Payload-identical across Addresses; "X" and "Y" differ. Grouping uses the technical tone name, not Unit-specific meaning. |
| F-10 | EAS: the same header with five areas received from two stations; a header differing in event code or issue time; repeated headers/EOM | One Transmission per receiving Gateway with five Transmission target areas; station ID is a Transmission attribute, so Transmissions from both stations may join the same Message. Different event code or issue time is different Payload. The Gateway adapter handles header/EOM repetition and assembly; audio/video is not processed in this version. |
| F-10a | Truncated/bit-error A and fuller B with different canonical values, either arrival order, with/without Incomplete marker; additional similar C | Preserve originals, but no heuristic joins/reconsideration. Different canonical values remain separate Messages; repeated equal partial values can group exactly under W. No active text/default/threshold settings or split jobs. |
| F-10b | Canonically equal originals A/B/C in one Message: A marked incomplete accepted first, B/C unmarked at the same later Acceptance time; preferred B/C hidden for another user | Prefer readable unmarked member, tie-break ascending ID. Restricted view uses same rule within readable exact members and qualifies marked-only fallback. Preserve originals/times; canonically different fuller input does not replace this Message's text. No synthetic or hidden text. |
| F-10c | Finalized valid text report with truncated Payload and multiple exact original Addresses; compare a report missing required fields, and the valid report retried with the same Submission ID | Store the truncated original and every Address/Function; resolve targets independently, keep one membership for the entire Transmission. W=0 still creates only one Message for that report and disables heuristic joining too. Invalid transport shape is rejected as a whole; retry creates no new evidence or support. No decoder fragment reassembly is added to the server. |
| F-10d | Exact components A/C outside W; partial B between resembles both but is canonically different; independently test equal Payload at 0/25/50 seconds under W=30 | B remains separate and cannot bridge A/C. Exact 0/25/50 forms one component regardless of arrival order. Heuristic evaluation is absent, not pending/blocking publication. |
| F-10e | Accepted original declaration resolves to N1; current mapping is changed to another permitted N2, or ceases to allow a safe resolution; Unit filter changes independently | Preserve original declaration/receipt and Payload/membership. Rematch current Network/target resolution and contributions, without requiring immutable rule/mapping version entities. Invalidate affected stale derivations; unresolved current configuration is explicit pending/failed manager state, not fabricated success or retroactive intake rejection. Unit-filter-only changes never alter Payload identity or membership. |
| F-11 | Same Message has contribution X in Network A/Unit X and Y in Network B/Unit Y; filter Network A AND Unit Y | No result: non-time dimensions match the same contribution. Network A AND Unit X matches. Gateway diagnostics require actual supporting evidence, not another unrelated member. |
| F-11a | Ten independent receptions, same Message/Network/Address/Function/current Unit, one or ten Gateways, times 12:00:00..12:00:09 | Ten originals and stored target resolutions, ten Contribution supports, one shared Message contribution. Contribution time 12:00:00; repeated technical Unit values do not mean ten user appearances/facts. Retry adds neither original nor support. |
| F-11b | One Message: Unit A first 12:00:00, Unit B first 12:00:20; query interval [12:00:10,12:00:30) | Unit A only: absent. Unit B only: one row at 12:00:20. A OR B: one row at 12:00:20. No Unit filter: one row at 12:00:20. No time/Unit filter: one row at 12:00:00. Global stored Message time always remains 12:00:00; it is not returned as this view's sort key. |
| F-11c | Same Unit A has Address X first 12:00:00 and Address Y first 12:00:20 in the same non-time filter scope; query [12:00:10,12:00:30) | A's appearance is first computed as 12:00:00, so absent. Do not time-filter Y first and falsely report a new first appearance. If an explicit Network/Address filter excludes X, the scoped appearance can be 12:00:20; filter identity is part of view/cursor state. |
| F-11d | Unit A first 12:00:00 is hidden/suppressed; permitted Unit B first 12:00:20 in the same Message | Unrestricted permitted view shows one row at 12:00:20, no A label/count/time metadata. Internal Message time 12:00:00 is not leaked. With B also hidden the Message is absent, not without-Unit. |
| F-11e | One Transmission at 12:00:00 reports X/Y resolving to different Units; another Gateway repeats at 12:00:02 | With Grouping: one Message, two shared contributions, two original receptions, four target resolutions/supports. First times stay 12:00:00. With W=0 each independent Transmission has its own Message; neither multi-target input splits by Unit. |
| F-11f | Address X at 12:00:00/12:00:20 in one Message; retroactive rule boundary at 12:00:10 moves X from A to B | Invalidate stale state; update original targets' derived resolutions and publish separate Unit A/B contributions with times 12:00:00/12:00:20. B matches [12:00:10,12:00:30). Originals and Message identity unchanged. If different rule/validity segments yield the same Unit/context, they may share a contribution; no mandatory rule-version entity. |
| F-11g | Merge/older late evidence changes a previously loaded result's first permitted time from 12:00:20 to 12:00:00; page cursor was issued at the old position | Update/reposition the same Message ID or remove it if now outside the interval; absorbed aliases resolve only after current authorization. Old continuation state resyncs when its sort summary is no longer reproducible. No duplicate/partial Message page or silent gap. |
| F-11h | Server now 12:01:00, max age 30 s; Unit A first 12:00:00 repeats at 12:00:50, genuinely new Unit B first 12:00:50 | A is expired despite repeat; B can be eligible through its own grant. No old A details/Delivery through B. Future first Observation 13:00 accepted at 12:00:50 uses capped age anchor 12:00:50, not 13:00. Default unlimited age still displays first times, never latest-reception times. |
| F-11i | One contribution has reception 12:00:00 via X and 12:00:02 via Y; only X suppressed; targetless POCSAG evidence in permitted N | Invalidate/rebuild usable supports/minimum to 12:00:02 without deleting either original. Narrower permission scopes never expose hidden minima. Targetless contribution needs N/without-Unit access, has Transmission-only supports and no synthetic Address/Unit; Unit filters cannot match it. |
| F-12 | Message contains permitted and hidden/suppressed Transmission target | Permitted projection only; no foreign counts/names/time/change metadata, no artificial 'Without Unit'. |
| F-13 | Message contains only suppressed/unreadable Transmission targets | No normal result/detail/live/Delivery Payload. |
| F-14 | Search `.*`, `%`, `_`, empty/short terms, letter case, accented characters | Literal substrings; empty means no text filter; accents distinct. Shared defined expectations for Unicode composition/case folding on both backends. |
| F-15 | Unit deleted or rule changed retroactively; two Addresses previously resolved to A, only one now resolves to B | Correct target resolutions, Contribution supports/contributions and first times from originals. Only affected Address moves; A remains for the other. Current checked publication prevents old jobs restoring stale derivations. No new Transmission/Message or regrouping; reconcile views/cursors. |
| F-16 | Organization deleted, Unit partly inherits defaults and partly overrides | Unit survives; applied defaults retained; no rematch; current organization filters/rights follow detachment. |
| F-17 | Session/grant/subscription revoked before new query/SSE Domain event/retry | No new unauthorized output; old cache/Payload is not evidence. Test in-flight boundary separately. |
| F-18 | Provider accepts, response lost, job lease expires | Uncertain external outcome; no exactly-once claim or blind endless retries. |
| F-19 | Disk full / primary authority uncertain / crash after possible commit | Visible honest acceptance/job state; no silent default deletion or divergent write. |
| F-20 | Wasm infinite loop, blocking host call, oversized result, secret in error | Cancel at configured C-10/shared limits, reject oversized/invalid result and redact secrets; visible failed/uncertain outcome as appropriate. Runtime enforcement is AP-03/AP-11 evidence, not an AP-02 passing test or hostile-code guarantee. |
| F-21 | Rule preview with hidden text or reaction with external target | No unauthorized extracted output or real Delivery through preview. |
| F-22 | Account deletion with pending attempts, audit, multiple credentials | Immediately end access/subscriptions, remove personal fields per C-13; retain distinct non-authenticating Deleted Principal IDs (pseudonymization, not anonymity). Durable cleanup failure stays visible without restoring access. Previously started effects remain accepted/uncertain honestly. |
| F-23 | Retention cutoff 12:00:10; Message origin 12:00:00, new Unit first 12:00:20; prepared independent Delivery versus reference-only work | Whole Message eligible despite recent Unit/View time; delete contributions/supports/target resolutions/evidence consistently, no regrouping of others. Self-contained work can finish under current checks/expiry; reference-only fails dependency-unavailable. Ordinary restart preserves dedup; manual Backup/Restore is external Operator work (D-31). Later Gateway retry after receipt deletion creates a new Transmission (C-01). |
| F-24 | Grant scope object deleted, API key restricted, guest without grants | No scope expansion, key never exceeds owner, guest has no implicit access. |
| F-25 | Several Full workers claim same work; old worker writes after lease loss | No unauthorized overwrite by superseded claim; external I/O remains separately uncertain. |
| F-26 | English UI/text catalog, parameterized/plural Localized text, missing Localized text mapping, independent formatting locale | English fallback under the defined mapping, complete keys/parameters/plurals, localized formatting independent of UI language; stable API codes/permissions/search and unchanged original Payload/operator-authored data. No second translated catalog required. |
